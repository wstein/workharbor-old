# Next alpha QA test plan

Planning snapshot: 11 October 2026. The tentative candidate is
`v0.1.0-alpha.6`; no tag is reserved and no row below has passed merely because
it is written here. Read the [release plan](v0.1.0-alpha.6-plan.md) for scope,
source snapshot and approval gates, and [requirements v3](../content/docs/requirements.md)
for the requirement definitions.

## Entry gate

Record one full integrated candidate SHA, reviewed source commits, required
review quorum and exact-SHA clear results. Resolve scope #533–#538 and dependency
#542/#27/#230/#283/#35 dispositions. The incomplete #535 service duration removal,
correlated tool events and tool-only abort, and #533 hard disk quota/security
decision are blockers until resolved or explicitly decided through the human
process. Do not count a configuration retirement as service behavior coverage.

Before target tests, obtain explicit human authorization for every build,
installation and host/runtime change needed. Use a disposable reference setup,
a scratch repository, a separate external test identity and disposable test
secrets. Record the real host/runtime versions and capabilities, stock language
image digest, BundleDock toolbox digest, agent CLI versions, guest shim/proxy
digests, installed binary digest/version, configuration and network path.
Use isolated writable HOME, caches and virtual environments outside the toolbox;
never use host credential stores. No host home, `~/.ssh` or runtime socket may
be mounted into a guest. Never expose real secret values in evidence.

## Evidence rules

Every case records requirement IDs, exact SHA, setup, action, expected and actual
result, timestamps, exit status, sanitized evidence location, reviewer and
`pass`, `fail`, `blocked` or `unverified`. Keep raw evidence in a restricted
location and link sanitized durable evidence from the issue. Record missing
coverage rather than treating an empty log as success.

Source tests with fakes establish contract/regression behavior only. Real target
acceptance uses the installed approved candidate, actual runtime and agent CLI;
record its evidence separately. Re-run affected cases after a relevant change.
A different integrated SHA must have fresh applicable review and checks. A live
run itself needs a human request; timers, quota reset, login recovery and restart
must never mint initiation or automatically start, resume or retry.

## Upgrade, rollback and distribution

These cases require separate human-approved builds and installations. Preserve
alpha.5's approved archive, digest and provenance before replacing it. Follow the
[backup/restore manual](../content/docs/manual/install-upgrade-release.md#back-up-upgrade-and-restore)
with the supervisor and environments stopped consistently. Encrypt backups of
secret files, preserve database/WAL/SHM and workspace/topic state together, and
exclude agent-home volumes and images. Do not execute the manual's provisional
commands here without checking the installed candidate and authorization.

## Exit gate

**Go:** every applicable mandatory case passes with actual target evidence on
the frozen candidate, required reviews/checks pass, and the human approves the
concrete release action. **No-go:** a mandatory case fails, is blocked or remains
unverified; the tool-event/abort, quota/security or forge-proof gate remains open;
or a claimed optional integration lacks acceptance. An approved deferral changes
scope and notes, never a test result.


Collect a matrix with every row's result and evidence against the exact candidate,
review quorum, dependency decisions, build/install approvals and upgrade/rollback
record. No mandatory target case is closed by fake-backed success. Outstanding
optional support is explicitly unverified with a follow-up and human scope
approval. Secrets, forbidden mounts, forge permission bypass, automatic starts,
run-wide watchdog cancellation, unsupported quota claims and failed provenance
block publication. The human reviews the concrete candidate and evidence before
approving a tag, publication or consumer activation; this document grants none
of those approvals.
